# Unified workspaces and top-bar notifications

The shared header now has an authenticated notification bell. A red dot indicates at least one unread saved update; the accessible name announces the count. The46px bell remains visible with the mobile menu closed. It opens the existing inbox and does not mark deliveries read. Auth/sign-in, restricted-account and saved-document/print headers retain their intentional compact form.

`GET /api/notifications/count` authenticates the actual stored actor and returns only that actor's identifier, unread count and preparation time. Client recipient/filter overrides are rejected, responses are no-store and the endpoint has its own rate budget. Counting shares the exact delivered-recipient/read-receipt source with the inbox, including original legacy read timestamps. It does not return messages or source targets and cannot write read receipts.

The bell refreshes every30seconds while visible, on return to the page, on route navigation and after confirmed inbox refresh/read changes. Same-origin storage events trigger a fresh recipient-scoped count when another tab records a read; no notification contents are stored there. Requests do not overlap, time out and abort on unmount. Actor changes reset state, mismatched actors are ignored, temporary failures retain the last confirmed count, and denied access clears private state. The inbox announces updates without moving unrelated keyboard focus. Opening the mobile menu moves focus to its first link; Escape closes it and restores the toggle.

## Three grouped areas

- **My vehicles** is one sidebar entry. Vehicles, Calendars, Earnings and Reports use a common section navigator, including their saved detail pages. Existing routes and ownership/tenant controls remain intact. The selected financial-record environment travels with tab links and the report's return-to-earnings link. This groups related tools without combining private owner finance with agency-wide accounting.
- **Account** has Security and Privacy & requests sections under `/workspace/account`. Privacy uses `?section=privacy` and preserves its filters/history pagination. Active legacy `/account-status` links redirect there with their filter/page preserved. Saved request-detail URLs still work and select the privacy section. Restricted identities retain their limited `/account-status` portal, without security/workspace access being expanded.
- **Agency partnership** combines the real six-section application guide with the saved application. New applicants see the create-draft action and expanded guide; existing applications retain the guide in a disclosure. Reading it never creates or submits a draft. Signed-in top-bar For agencies links go directly to this area. The public partnership page retains the same reusable guide and application entry for visitors.

Notifications, the separate account/privacy entry, the separate vehicle-calendar/earnings/report entries and the separate partnership-guide entry are removed from the ordinary sidebar. Role-specific agency/platform operations retain their own scopes. Privacy submissions, document consent, approval, financial records and application workflow rules are unchanged.
