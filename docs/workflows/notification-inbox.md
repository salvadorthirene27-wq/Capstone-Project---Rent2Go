# Recipient notification inbox

The workspace Notifications page combines saved agency-partnership, booking and owner-account deliveries. Migration029 adds vehicle deliveries and immutable read receipts. It does not send email, move funds, approve an agreement or fabricate historical notifications.

## Delivery and source access

Existing delivered records retain their original timestamps and messages. New vehicle transitions deliver fixed, minimal messages in the same transaction as the saved vehicle event. Recipients are the original personal owner, applicable active agency operators and independent platform compliance reviewers. Accepting a renter assessment that affects a consigned vehicle also delivers an owner-specific allocation-review reminder through the exact saved quotation/vehicle/owner relationship. Rollback removes the related delivery. No old vehicle event is backfilled as a past delivery.

Every query first restricts the delivered recipient to the authenticated stored actor. The client cannot choose another recipient or gain authority through a forged role. Current source permissions then determine message and link visibility. Removed members and unavailable agencies do not expose private saved reasons or source identifiers through old agency notifications; a generic retained notice replaces those details. Original owners and renters can still access their own historical records when an agency is unavailable. Super Admin has no implicit access to whole-booking or private payout details. Fixture and suspended actors are denied. Simulated owner-account messages are explicitly labeled using the account's saved financial environment.

## Read lifecycle and interface

Users can filter all/unread and category, refresh, page through20 records and open protected source workspaces. They explicitly mark one update or only the displayed page as read. A batch accepts at most20 unique source/ID pairs, verifies every delivered recipient and fails atomically for a foreign/missing entry. The first read timestamp persists under concurrent and identical retries; a previous legacy read timestamp is preserved. Database guards reject forged receipt ownership, content rewrites, deletion and changed prior read times. Receipt insertion rechecks current actor suspension under an authorization lock.

The interface uses the shared forest/mint workspace theme and navigation. Read/unread states use text and borders, not color alone. Visible-page refresh occurs every30seconds and on foreground/focus, with a manual refresh control. Background refresh announces new unread activity without moving focus or marking it read. Explicit read completion focuses its status feedback when a read button disappears. Failed refreshes keep the last loaded data under its actual filters with retry guidance; busy controls prevent duplicate or overlapping operations. Requests abort and timers/listeners clean up when leaving the inbox. Links retain normal protected source authorization and do not execute business actions.
